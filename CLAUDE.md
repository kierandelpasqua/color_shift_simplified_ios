# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Native SwiftUI port (iPhone only, iOS 26+, portrait, dark) of the **Color Shift** web app: a photo-driven
color pairing tool that derives a foreground/background pair from each photo and scores it with WCAG and
APCA contrast. The aim is behavioral parity with the web, plus native polish.

| File | Role |
|---|---|
| [`prd.md`](prd.md) | Requirements as an **ordered task list**. Work is done one task per iteration (§0 has the loop rules). |
| [`ios.md`](ios.md) | Port plan: decisions (I1–I10), architecture, engine, motion, accessibility, testing. Cited as "ios.md §n". |
| [`PROJECT_MAP.md`](PROJECT_MAP.md) | **Read-only** snapshot of the web repo's reference (behavior, algorithms, test vectors). Cited as "PM §n". |

When `prd.md` and `ios.md` disagree, fix whichever one is wrong in the same commit.

## The web repo is the source; this repo is the only place to write

The reference implementation is at `~/GitHub/Color_Shift_Simplified_web/Build Color Shift Simplified/`
(React/Vite, color logic in `src/`). **Read it; never modify it.** Copy any assets you need (such as photos)
into this repo, so it builds on its own. If the web's `PROJECT_MAP.md` changes, re-copy it here (ios.md §19).

## Commands

The Xcode project is generated by XcodeGen and is not committed. Run `xcodegen generate` after cloning,
after editing `project.yml`, or after adding or removing source files.

```bash
xcodegen generate

# BUILD
xcodebuild -project ColorShift.xcodeproj -scheme ColorShift \
  -destination 'platform=iOS Simulator,name=iPhone 18 Pro' build

# UNIT (Swift Testing)
xcodebuild -project ColorShift.xcodeproj -scheme ColorShift \
  -destination 'platform=iOS Simulator,name=iPhone 18 Pro' -only-testing:ColorShiftTests test

# A single test (Swift Testing identifiers keep the trailing "()")
xcodebuild -project ColorShift.xcodeproj -scheme ColorShift \
  -destination 'platform=iOS Simulator,name=iPhone 18 Pro' \
  -only-testing:'ColorShiftTests/AppConfigTests/urlSchemeMatchesInfoPlist()' test

# UI (XCUITest)
xcodebuild -project ColorShift.xcodeproj -scheme ColorShift \
  -destination 'platform=iOS Simulator,name=iPhone 18 Pro' -only-testing:ColorShiftUITests test
```

In `prd.md`, **BUILD / UNIT / UI** refer to the commands above, and **BUILD@Duo** means BUILD with
`name=iPhone Duo`. Test devices are iPhone 18 Pro (default), iPhone 17e (small), iPhone 18 Pro Max and
iPhone Duo. There is no linter; the app target treats warnings as errors, so the build is the check.

## Working the task loop (summary of prd.md §0)

- Do the **first** `[ ]` task in prd.md §5 that isn't tagged `HUMAN` and whose `Depends` are all `[x]`.
  Read its `Refs` first, implement **only that task**, and run its `Verify` line.
- When it passes, tick `[x]`, append one line to the §6 Progress log, and commit as `T-0xx: <title>`,
  staging files by explicit path. Push only when the last task of a phase is ticked.
- If it can't pass, or needs a decision: mark it `[!]`, add a `Blocked:` note, log it, commit, and stop.
- Never tick a box without a passing Verify, and never weaken a test.
- `HUMAN` tasks (name, enrollment, URLs, fonts) are for the owner. Never tick them, download files, create
  accounts or submit anything.

## Architecture (ios.md §5)

```
ColorShift/
  App/        ColorShiftApp (@main, dark, onOpenURL), AppConfig (owner placeholders)
  Model/      Theme, Photo, PhotoCatalog (the 12 photos in web order)
  Engine/     SRGB8, ColorMath (WCAG, tune, layoutShares), APCA, PhotoSampler   ← pure, nonisolated
  State/      AppModel: one @Observable mirroring the web's state (PM §6) and its actions
  Design/     Tokens, Typography (Dynamic Type), Motion
  Views/      RootView (canvas + push drawer), Specimen, PhotoPanel, MixerToggle, AboutSheet, Deck/…
  Resources/  Info.plist (generated from project.yml), Photos/ (JPEG bundle files), Fonts/, assets
ColorShiftTests/    Swift Testing: engine vectors, AppModel behavior, token contrast
ColorShiftUITests/  XCUITest smoke flow
```

Data flow: views → `AppModel` actions → state stored as `SRGB8` → derived values (hex, HSL, WCAG, APCA) are
computed properties → views convert to `Color` at the edge. `PhotoSampler` derives a pair when a photo
loads, unless a deep link just set both colors (`preserveLinkedColors` skips one derivation).

## Conventions and invariants

- **No third-party Swift dependencies.** XcodeGen is the only extra tool.
- **Concurrency:** Swift 6, Default Actor Isolation = MainActor. Engine types are `nonisolated`, `Sendable`
  value types, so tests call them synchronously. The sampler runs `@concurrent`, off the main actor. The UI
  test target is set to `nonisolated` because `XCTestCase` overrides can't be MainActor.
- **Colors are `SRGB8`** (8-bit sRGB, exactly what a hex string holds). HSL is derived from it. A color is
  only rewritten from HSL when a slider actually moves, so values never drift.
- **Port the web's math verbatim** (PM §8, rounding notes in PM §8.13). The one exception is APCA: use real
  APCA 0.0.98G-4g, which gives signed Lc values (ios.md §7). Shared test vectors must pass in both codebases.
- **Photo catalog order matches the web exactly (I9).** Shared links use `photo=N`, the 0-based index into
  the full catalog (not the filtered list). Never reorder the catalog.
- **Share link format** stays the web's: `https://<web-host>/?fg=RRGGBB&bg=RRGGBB&photo=N`.
  `colorshift://pair?…` is for opening links in the app only.
- **Motion constants live only in `Design/Motion.swift`**, each with a Reduce Motion variant.
- **Owner placeholders** (bundle ID, web URL, privacy URL) live only in `ColorShift/App/AppConfig.swift`,
  marked `// TODO(H-0x)`. The bundle ID also appears in `project.yml`, so keep the two in sync.
- **Intentional divergences** from the web (APCA, type scale, fixed web bugs) are recorded in ios.md §2/§14.
